# Справочник Turnable &nbsp;·&nbsp; [🇬🇧 EN](REFERENCE.md)
## Типы подключения
| Тип      | Описание                                                                                             |
|----------|------------------------------------------------------------------------------------------------------|
| `relay`  | Туннелирует трафик через TURN сервер платформы на шлюз сервера Turnable.                             |
| `direct` | Туннелирует трафик через TURN сервер платформы напрямую на конечный сервер. **⚠️ Не рекомендуется.** |
| `p2p`    | Скрывает трафик в поддельных трансляциях через SFU платформы. **⚠️ WIP**                             |


## Протоколы
| Протокол | Описание                                                                  |
|----------|---------------------------------------------------------------------------|
| `none`   | Без протокола вообще. **⚠️ Не рекомендуется и опасно использовать.**      |
| `dtls`   | Чистый DTLS. Простой, но легко обнаруживается. Только режим `relay`.      |
| `srtp`   | DTLS+SRTP. Имитирует настоящий медиатрафик. Принудительно в режиме `p2p`. |

## Транспорты
| Транспорт | Описание                                                                                                                      |
|-----------|-------------------------------------------------------------------------------------------------------------------------------|
| `none`    | Без транспортного протокола. Используй только для UDP маршрутов.                                                              |
| `kcp`     | [KCP](https://github.com/xtaci/kcp-go) - надежный и стабильный упорядоченный поток по UDP. Рекомендуется для TCP маршрутов.   |
| `sctp`    | [SCTP](https://en.wikipedia.org/wiki/Stream_Control_Transmission_Protocol) - поддерживается, но не идеален. Не рекомендуется. |

## Типы сокетов
| Сокет | Описание                                                                                                 |
|-------|----------------------------------------------------------------------------------------------------------|
| `tcp` | [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol) соединение (для VLESS, Trojan, и др.) |
| `udp` | [UDP](https://en.wikipedia.org/wiki/User_Datagram_Protocol) соединение (для WireGuard, Hysteria, и др.)  |

## Транспорты сессии
Только для режима Relay, выбирается полем `mux` клиента. Сервер принимает оба.

| Mux      | Описание |
|----------|----------|
| `mpath`  | По умолчанию. Одна multipath-сессия поверх всех пиров: каждый пир это путь со своими номерами пакетов, ACK, RTT, обнаружением потерь и пейсером (стартует с ~180 КБ/с, узнаёт реальный лимит, отступает при полисинге). Пакет уходит в пир, который доставит его раньше всех; надёжные данные собираются обратно из всех пиров, поэтому переупорядочивание не вызывает повторных отправок. Мёртвые пиры (нет ACK 1.5 с) отключаются и переподключаются, не мешая потокам. TCP-маршруты это потоки, UDP-маршруты это датаграммы. Всегда сквозное шифрование (ML-KEM-768 + X25519, AES-256-GCM), сервер проверяется по `pub_key`. |
| `legacy` | Прежний стек: транспорт маршрута (KCP/SCTP) поверх tinymux, пакеты раскидываются по пирам по кругу. Оставлен для старых серверов. |

При `mpath` опция `mask=on` (по умолчанию) договаривается о дешёвом маскировании вместо внешнего шифрования записей DTLS/SRTP, так как данные уже зашифрованы: форма и размеры записей не меняются, маскируется только начало полезной нагрузки. Старые серверы игнорируют предложение и остаются с полным шифрованием.

## Режимы шифрования
| Режим       | Описание                                              |
|-------------|-------------------------------------------------------|
| `handshake` | Шифрует только рукопожатие. Быстрее, меньше нагрузка. |
| `full`      | Шифрует весь трафик сквозным шифрованием.             |
